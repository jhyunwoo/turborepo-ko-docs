Turborepo는 **모든 저장소, 단일 또는 다중 패키지**에 점진적으로 채택되어 저장소의 개발자 및 CI 워크플로우 속도를 높일 수 있습니다.

`turbo`을 설치하고 `turbo.json`에서 작업을 구성한 후에는 [캐싱](/docs/crafting-your-repository/caching)이 작업을 훨씬 더 빠르게 실행하는 데 어떻게 도움이 되는지 알게 될 것입니다.

## 단일 패키지 작업공간 준비

예를 들어 [단일 패키지 작업공간](https://vercel.com/docs/vercel-platform/glossary#single-package-workspace)은 `npx create-next-app` 또는 `npm create vite`을 실행한 후 얻는 것입니다. Turborepo가 ​​리포지토리를 처리하기 위해 추가 작업을 수행할 필요가 없으므로 아래 첫 번째 단계로 이동할 수 있습니다.

단일 패키지 작업공간의 Turborepo에 대해 자세히 알아보려면 [전용 가이드](/docs/guides/single-package-workspaces)를 방문하세요.

## 다중 패키지 작업 공간 준비(monorepo)

`turbo`은 JavaScript 생태계의 주요 패키지 관리자 기능인 작업공간을 기반으로 구축되었습니다. 이를 통해 기존 코드베이스에 쉽게 채택할 수 있습니다.

<Callout type="info">
  `turbo`에 액세스할 수 없는 등의 문제가 있는 경우
 작업 공간에서 패키지를 발견하거나 종속성 그래프를 따르지 않는 경우
 우리의 [구조화
 저장소](/docs/crafting-your-repository/structuring-a-repository) 페이지
 팁.
</Callout>

_모든_ 작업을 위해 _모든_ 작업 실행을 시작할 필요는 없습니다.
`turbo`을 사용하여 즉시 패키지를 만듭니다. 한 번에 하나의 작업으로 시작할 수 있습니다.
패키지 수가 적고 더 많은 작업과 패키지를 점진적으로 추가합니다.
Turborepo(Turborepo)에 대해 잘 알고 있습니다.

## 저장소에 Turborepo 추가

<Steps>
<Step>
### `turbo` 설치

최고의 개발자 경험을 위해서는 `turbo`을 전역적으로 설치하고 저장소 루트에 설치하는 것이 좋습니다.

<PackageManagerTabs>
  <Tab value="pnpm">
      설치를 시작하기 전에 `pnpm-workspace.yaml` 파일을 생성했는지 확인하세요. 이 파일이 없으면 ` --workspace-root may only be used inside a workspace`이라는 오류가 발생합니다.

  ```bash title="단말기"
  # 전역 설치
  pnpm add turbo --global
  # 저장소에 설치
  pnpm add turbo --save-dev --workspace-root
  ```

  </Tab>
  <Tab value="yarn">

    ```bash title="단말기"
  # 전역 설치
  yarn global add turbo
  # 저장소에 설치
  yarn add turbo --dev
  ```

  </Tab>
  <Tab value="npm">

    ```bash title="단말기"
  # 전역 설치
  npm install turbo --global
  # 저장소에 설치
  npm install turbo --save-dev
  ```

  </Tab>
  <Tab value="bun">

    ```bash title="단말기"
  # 전역 설치
  bun install turbo --global
  # 저장소에 설치
  bun install turbo --dev
  ```

  </Tab>
</PackageManagerTabs>

두 설치를 모두 권장하는 이유에 대해 자세히 알아보려면 [설치 페이지](/docs/getting-started/installation)를 방문하세요.

</Step>
<Step>

### `turbo.json` 파일 추가

저장소 루트에 `turbo.json` 파일을 생성합니다.

이 가이드에서는 `build` 및 `check-types` 작업을 사용하지만 `lint` 또는 `test` 등 관심 있는 다른 작업으로 대체할 수 있습니다.

<Tabs items={['Next.js', 'Vite']} storageKey="framework-preference">
  <Tab value="Next.js">
```json title="./turbo.json"
{
  "$schema": "https://turborepo.dev/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": [".next/**", "!.next/cache/**"]
    },
    "check-types": {
      "dependsOn": ["^check-types"]
    },
    "dev": {
      "persistent": true,
      "cache": false
    }
  }
}
```

`turbo.json` 구성에 대한 자세한 내용은 [구성 옵션](/docs/reference/configuration) 문서를 참조하세요.

Next.js 애플리케이션에서 실행할 `turbo`에 대한 `check-types` 스크립트가 있는지 확인하세요.

```diff title="apps/web/package.json"
{
  "scripts": {
+   "check-types": "tsc --noEmit"
  }
}
```

  </Tab>
  <Tab value="Vite">
```json title="./turbo.json"
{
  "$schema": "https://turborepo.dev/schema.json",
  "tasks": {
    "build": {
      "outputs": ["dist/**"]
    },
    "check-types": {
      "dependsOn": ["^check-types"]
    },
    "dev": {
      "persistent": true,
      "cache": false
    }
  }
}
```

일부 Vite 스타터에는 다음과 같은 `package.json`이 함께 제공됩니다.

```json title="package.json"
{
  "scripts": {
    "build": "tsc && vite build"
  }
}
```

`turbo`이 병렬로 실행할 수 있도록 이를 `check-types` 및 `build` 스크립트로 분할하는 것이 좋습니다.

```json title="apps/web/package.json"
{
  "scripts": {
    "build": "vite build",
    "check-types": "tsc --noEmit"
  }
}
```

  </Tab>
</Tabs>

다중 패키지 작업 영역에서는 `check-types` 스크립트를 추가할 수도 있습니다.
여러 스크립트가 어떻게 교차하는지 확인하려면 하나 이상의 라이브러리 패키지에
하나의 `turbo` 명령으로 다양한 패키지가 실행됩니다.

</Step>
<Step>
### 편집 `.gitignore`

`.gitignore` 파일에 `.turbo`을 추가합니다. `turbo` CLI는 로그, 출력 및 기타 기능을 유지하기 위해 이러한 폴더를 사용합니다.

```diff title=".gitignore"
+ .turbo
```

</Step>
<Step>
### 루트 `package.json`에 `packageManager` 필드 추가

Turborepo는 패키지 관리자의 정보를 사용하여 저장소를 최적화합니다. 사용 중인 패키지 관리자를 선언하려면 [`packageManager`](https://nodejs.org/api/packages.html#packagemanager) 필드가 아직 없는 경우 루트 `package.json`에 추가하세요.

<PackageManagerTabs>

<Tab value="pnpm">

```diff title="package.json"
{
+  "packageManager": "pnpm@10.0.0"
}
```

</Tab>

<Tab value="yarn">

```diff title="package.json"
{
+  "packageManager": "yarn@1.22.19"
}
```

</Tab>

<Tab value="npm">

```diff title="package.json"
{
+  "packageManager": "npm@8.5.0"
}
```

</Tab>

<Tab value="bun">

```diff title="package.json"
{
+  "packageManager": "bun@1.2.0"
}
```

</Tab>

</PackageManagerTabs>

<Callout type="info">
  저장소에 따라 다음을 사용해야 할 수도 있습니다.
 [`dangerouslyDisablePackageManagerCheck`](/docs/reference/configuration#dangerouslydisablepackagemanagercheck)
 마이그레이션하는 동안 또는 `packageManager` 키를 사용할 수 없는 상황에서
 아직.
</Callout>

</Step>
<Step>
### 패키지 관리자 작업 영역 설정

[다중 패키지 작업공간](https://vercel.com/docs/glossary#multi-package-workspace)의 경우 작업공간 구조를 인식하도록 패키지 관리자를 구성해야 합니다.

`workspaces` 필드는 패키지 관리자에게 패키지가 포함된 디렉터리를 알려줍니다. 일반적인 패턴에는 애플리케이션용 `apps/*`과 공유 라이브러리용 `packages/*`이 포함됩니다.

<Callout type="info">
  단일 패키지 저장소로 작업하는 경우 다음과 같이 이 단계를 건너뛸 수 있습니다.
 작업 공간은 필요하지 않습니다.
</Callout>

<PackageManagerTabs>

  <Tab value="pnpm">
  ```json title="pnpm-workspace.yaml"
 packages:
  - "apps/*"
  - "packages/*"
 ```
  <LinkToDocumentation href="https://pnpm.io/pnpm-workspace_yaml" text="pnpm 작업 공간 문서" />

  </Tab>

  <Tab value="yarn">
  ```json title="./package.json"
 {
  "workspaces": [
   "apps/*",
   "packages/*"
  ]
 }
 ```

  <LinkToDocumentation href="https://yarnpkg.com/features/workspaces#how-are-workspaces-declared" text="원사 작업 공간 문서" />
   </Tab>

  <Tab value="npm">
  ```json title="./package.json"
 {
  "workspaces": [
   "apps/*",
   "packages/*"
  ]
 }
 ```

  <LinkToDocumentation href="https://docs.npmjs.com/cli/v7/using-npm/workspaces#defining-workspaces" text="npm 작업공간 문서" />
  </Tab>

  <Tab value="bun">
  ```json title="./package.json"
 {
  "workspaces": [
   "apps/*",
   "packages/*"
  ]
 }
 ```

  <LinkToDocumentation href="https://bun.sh/docs/install/workspaces" text="롤빵 작업 공간 문서" />
  </Tab>

</PackageManagerTabs>

저장소를 구성하는 방법에 대한 자세한 내용은 [저장소 구조화](/docs/crafting-your-repository/structuring-a-repository#declaring-directories-for-packages)를 참조하세요.

</Step>
<Step>
### `turbo`으로 작업 실행

이제 Turborepo를 사용하여 이전에 `turbo.json`에 추가한 작업을 실행할 수 있습니다. 위의 예제 작업을 사용하면 다음과 같습니다.

```bash title="Terminal"
turbo build check-types
```

그러면 `build` 및 `check-types` 작업이 동시에 실행됩니다. [작업 공간](/docs/crafting-your-repository/structuring-a-repository#anatomy-of-a-workspace)의 종속성 그래프는 작업을 올바른 순서로 실행하는 데 사용됩니다.

</Step>
<Step>
**코드를 변경하지 않고 `build` 및 `check-types`을 다시 실행해 보세요.**

```bash title="Terminal"
turbo check-types build
```

다음과 같은 터미널 출력이 표시되어야 합니다.

```bash title="Terminal"
Tasks:    2 successful, 2 total
Cached:    2 cached, 2 total
Time:    185ms >>> FULL TURBO
```

축하해요! **단 몇 밀리초 만에 코드를 작성하고 유형을 확인했습니다**.

`turbo`이 이를 가능하게 하는 방법에 대해 자세히 알아보려면 [캐싱 문서](/docs/crafting-your-repository/caching)를 확인하세요.

</Step>
<Step>

### `turbo`과 함께 `dev`을 실행하여 개발을 시작합니다.

다중 패키지 작업 영역에서는 `turbo dev`을 실행하여 모든 패키지에 대한 개발 작업을 한 번에 시작할 수 있습니다.

```bash title="Terminal"
turbo dev
```

또한 [필터를 사용](/docs/crafting-your-repository/running-tasks#using-filters)하여 특정 패키지와 해당 종속성에 집중할 수도 있습니다.

<Callout type="info">
이 단계는 다음과 같은 이유로 단일 패키지 작업 영역에서는 많은 가치를 제공하지 않습니다.

- 개발 작업에 대한 출력을 캐시하지 않습니다.
- 개발 스크립트가 하나뿐이므로 병렬로 실행할 것이 없습니다.

</Callout>

</Step>
