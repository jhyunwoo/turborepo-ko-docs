다음 예에서는 [GitLab CI](https://docs.gitlab.com/ee/ci/)와 함께 Turborepo를 사용하는 방법을 보여줍니다.

특정 루트 `package.json`의 경우:

```json title="./package.json"
{
  "name": "my-turborepo",
  "scripts": {
    "build": "turbo run build",
    "test": "turbo run test"
  },
  "devDependencies": {
    "turbo": "latest"
  }
}
```

그리고 `turbo.json`:

```json title="./turbo.json"
{
  "$schema": "https://turborepo.dev/schema.json",
  "tasks": {
    "build": {
      "outputs": [".svelte-kit/**"],
      "dependsOn": ["^build"]
    },
    "test": {
      "dependsOn": ["^build"]
    }
  }
}
```

다음 내용으로 저장소에 `.gitlab-ci.yml`이라는 파일을 만듭니다.

<PackageManagerTabs>

        ```yaml title=".gitlab-ci.yml"
    image: node:latest
    stages:
     - build
    build:
     stage: build
     before_script:
      - curl -f https://get.pnpm.io/v6.16.js | node - add --global pnpm@6.32.2

      - pnpm build
      - pnpm test

       files:
        - pnpm-lock.yaml
      paths:
       - .pnpm-store
    ```

## 원격 캐싱

원격 캐싱을 사용하려면 공급자의 원격 캐시에 대한 팀과 토큰을 검색하세요. 이 예에서는 [Vercel 원격 캐시](https://vercel.com/docs/monorepos/remote-caching)를 사용합니다.

- `TURBO_TOKEN` - 원격 캐시에 액세스하기 위한 Bearer 토큰
- `TURBO_TEAM` - 아티팩트를 공유하는 Vercel 팀의 슬러그

Vercel 원격 캐싱을 사용하려면 몇 단계를 거쳐 이러한 변수의 값을 얻을 수 있습니다.

1. [Vercel 대시보드](https://vercel.com/account/tokens)에서 계정에 대한 범위 지정 액세스 토큰을 생성합니다.

![Vercel 액세스 토큰](/images/docs/vercel-create-token.png)

값을 안전한 곳에 복사하세요. 곧 필요할 것입니다.

2. GitLab 저장소 설정으로 이동하여 **설정**을 클릭한 다음 **CI/CD** 탭을 클릭합니다. `TURBO_TOKEN`이라는 새 변수를 만들고 범위 지정 액세스 토큰 값을 입력합니다.

![GitLab CI 변수](/images/docs/gitlab-ci-variables.png)
![GitLab CI 변수 생성](/images/docs/gitlab-ci-create-variable.png)

3. `TURBO_TEAM`이라는 두 번째 비밀을 만들고 팀 슬러그에 설정합니다. - [팀 URL](https://vercel.com/d?to=%2F%5Bteam%5D%2F%7E%2Fsettings&title=Find+Team+URL)에서 `vercel.com/` 다음 부분입니다. 예를 들어 `vercel.com/acme`의 슬러그는 `acme`입니다.

이제 GitLab 워크플로에서 원격 캐싱이 작동됩니다.
