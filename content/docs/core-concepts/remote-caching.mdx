Turborepo의 [작업 캐시](/docs/crafting-your-repository/caching)는 동일한 작업을 두 번 수행하지 않아 시간을 절약합니다.

하지만 문제가 있습니다. **캐시는 컴퓨터의 로컬에 있습니다**. 지속적 통합 시스템으로 작업할 때 중복된 작업이 많이 발생할 수 있습니다.

Turborepo는 기본적으로 로컬 파일 시스템에만 캐시하므로 모든 작업 입력이 동일하더라도 동일한 작업(`turbo run build`)이 **각 시스템에서**(귀하, 팀 동료, CI, PaaS 등에 의해) 다시 실행되어야 합니다. 이는 **시간과 리소스를 낭비**합니다.

<Callout type="info">
  Turborepo를 사용하기 위해 원격 캐싱을 반드시 써야 하는 것은 아닙니다. 원격
  캐싱을 사용하면 가장 큰 폭의 속도 향상을 얻을 수 있지만, 원격 캐싱이 없어도
  기존 워크플로를 더 빠르게 만들 수 있습니다.
</Callout>

## 단일 공유 캐시

전체 팀(심지어 CI까지)에서 단일 Turborepo 캐시를 공유할 수 있다면 어떨까요?

Turborepo는 작업 결과를 저장하는 클라우드 서버인 원격 캐시와 안전하게 통신할 수 있습니다. 이렇게 하면 **조직 전체에서 중복된 작업을 방지**하여 엄청난 시간을 절약할 수 있습니다.

원격 캐싱은 무료이며 [관리형 제공업체](https://turborepo.dev/docs/core-concepts/remote-caching#managed-remote-cache-with-vercel) 또는 [자체 호스팅 캐시](https://turborepo.dev/docs/core-concepts/remote-caching#self-hosting)로 사용할 수 있습니다.

<Callout type="info">
  원격 캐싱은 Turborepo의 강력한 기능이지만 강력한 기능을 통해
 큰 책임이 따릅니다. 먼저 올바르게 캐싱하고 있는지 확인하고
 다시 확인 [환경 처리
 변수](/docs/crafting-your-repository/using-environment-variables). 제발
 또한 Turborepo는 로그를 아티팩트로 취급하므로 자신이 무엇인지 알고 있어야 합니다.
 콘솔에 인쇄합니다.
</Callout>

## Vercel

[Vercel 원격 캐시](https://vercel.com/docs/monorepos/remote-caching)는 Vercel에서 애플리케이션을 호스팅하지 않더라도 모든 요금제에서 무료로 사용할 수 있습니다. 리포지토리에 대한 원격 캐싱을 활성화하려면 아래 단계를 따르세요.

### 지역 발전을 위해

로컬 Turborepo를 원격 캐시에 연결하려면 Vercel 계정으로 Turborepo CLI를 인증하세요.

```bash title="Terminal"
turbo login
```

[global `turbo`](/docs/getting-started/installation#global-installation)이 설치되어 있지 않은 경우에도 패키지 관리자를 사용할 수 있습니다.

<PackageManagerTabs>

<Tab value="pnpm">

```bash title="Terminal"
pnpm dlx turbo login
```

</Tab>

<Tab value="yarn">

```bash title="Terminal"
yarn dlx turbo login
```

</Tab>

<Tab value="npm">

```bash title="Terminal"
npx turbo login
```

</Tab>

<Tab value="bun">

```bash title="Terminal"
bunx turbo login
```

</Tab>
</PackageManagerTabs>

<Callout type="info">
  원격 캐시가 Single-Sign-On을 사용하도록 구성된 경우 다음을 실행해야 합니다.
 `npx turbo login --sso-team=team-name` 캐시 토큰을 얻기 위해
 올바른 권한.
</Callout>

이제 Turborepo를 원격 캐시에 연결하십시오.

```bash title="Terminal"
turbo link
```

활성화되면 현재 캐싱 중인 패키지를 일부 변경하고 `turbo run`을 사용하여 이에 대해 작업을 실행합니다.
이제 캐시 아티팩트가 원격 캐시에 로컬로 _및_ 저장됩니다.

확인하려면 다음을 사용하여 로컬 Turborepo 캐시를 삭제하세요.

<PlatformTabs>
  <Tab>

    ```bash title="단말기"
  rm -rf ./.turbo/cache
  ```

  </Tab>
  <Tab>

    ```bash title="단말기"
  rd /s /q "./.turbo/cache"
  ```

  </Tab>
</PlatformTabs>

그런 다음 동일한 빌드를 다시 실행하십시오. 제대로 작동한다면 `turbo`은 작업을 로컬에서 실행해서는 안 됩니다. 대신 원격 캐시에서 로그와 아티팩트를 다운로드하여 다시 재생합니다.

### Vercel의 원격 캐싱

Vercel에서 앱을 구축하고 호스팅하는 경우 `turbo`을 사용하면 원격 캐싱이 자동으로 설정됩니다. 자세한 내용은 [Vercel 문서](https://vercel.com/docs/concepts/monorepos/remote-caching?utm_source=turborepo.dev&utm_medium=referral&utm_campaign=docs-link)를 참조하세요.

### 유물 무결성 및 진위성 검증

Turborepo는 원격 캐시에 업로드하기 전에 비밀 키로 아티팩트에 서명할 수 있습니다. Turborepo는 귀하가 제공한 비밀 키를 사용하여 아티팩트에 `HMAC-SHA256` 서명을 사용합니다.
Turborepo는 다운로드 시 원격 캐시 아티팩트의 무결성과 신뢰성을 확인합니다.
확인에 실패한 모든 아티팩트는 무시되며 Turborepo에서는 캐시 누락으로 처리됩니다.

이 기능을 활성화하려면 `turbo.json` 구성에서 `remoteCache` 옵션을 설정하여 `signature: true`을 포함하세요. 그런 다음 `TURBO_REMOTE_CACHE_SIGNATURE_KEY` 환경 변수를 선언하여 비밀 키를 지정합니다.

```jsonc title="./turbo.json"
{
  "remoteCache": {
    "signature": true, // [!code highlight]
  },
}
```

## 원격 캐시 API

원격 캐시는 Turborepo의 원격 캐싱 API 사양을 충족하는 모든 HTTP 서버에서 구현할 수 있습니다.

### Vercel을 사용한 관리형 원격 캐시

Turborepo의 제작자이자 유지관리자인 [Vercel](https://vercel.com)은 Turborepo와 완벽하게 호환되는 관리형 원격 캐시를 제공합니다.

[Vercel 원격 캐시](https://vercel.com/docs/monorepos/remote-caching)를 사용하면 구성이 필요 없으며 오픈 소스 [Vercel 원격 캐시 SDK](https://vercel.com/docs/deployments/overview)를 통해 [Vercel 배포](https://github.com/vercel/remote-cache)와 자동으로 통합됩니다.

[Vercel의 Turborepo](https://vercel.com/docs/monorepos/turborepo)에 대해 자세히 알아보거나 [무료 템플릿 배포](https://vercel.com/templates?search=turborepo)를 사용해 보세요.

### 자체 호스팅

또한 자체 원격 캐시를 자체 호스팅하고 `--manual` 플래그를 사용하여 로그인하여 API URL, 팀 및 토큰 정보를 제공할 수도 있습니다.

```bash title="Terminal"
turbo login --manual
```

#### OpenAPI 사양

- [사람이 읽을 수 있는 뷰어](/docs/openapi)
- [JSON](/api/remote-cache-spec)

현재 `turbo`의 모든 버전은 `v8` 엔드포인트와 호환됩니다.
