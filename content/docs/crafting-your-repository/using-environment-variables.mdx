환경 변수 입력은 Turborepo 구성에서 고려해야 하는 애플리케이션의 중요한 부분입니다.

Turborepo에서 환경 변수로 작업할 때 세 가지 중요한 질문이 있습니다.

- [작업 해시에 내 환경 변수가 포함되어 있나요?](#adding-environment-variables-to-task-hashes)
- [`turbo`은 어떤 환경 모드를 사용하나요?](#environment-modes)
- [`.env` 파일을 처리했나요?](#handling-env-files)

<Callout type="error">
  구성에서 환경 변수를 고려하지 않으면 다음과 같은 결과가 발생할 수 있습니다.
 잘못된 구성으로 애플리케이션을 배송하는 중입니다. 이로 인해 발생할 수 있는
 미리보기 배포를 프로덕션으로 배송하는 것과 같은 심각한 문제입니다.
</Callout>

<Callout type="info">
  Turborepo는 또한 [시스템 환경
 변수](/docs/reference/system-environment-variables)를 사용하여 자체 구성
 행동. 아래에서 귀하의 환경 변수에 대한 정보를 찾을 수 있습니다.
 작업의 런타임 및 작업 해싱에 미치는 영향.
</Callout>

## 작업 해시에 환경 변수 추가

Turborepo는 애플리케이션 동작의 변경 사항을 설명하기 위해 환경 변수를 인식해야 합니다. 이렇게 하려면 `turbo.json` 파일에서 `env` 및 `globalEnv` 키를 사용하세요.

```json title="./turbo.json"
{
  "globalEnv": ["IMPORTANT_GLOBAL_VARIABLE"],
  "tasks": {
    "build": {
      "env": ["MY_API_URL", "MY_API_KEY"]
    }
  }
}
```

- **globalEnv**: 이 목록의 환경 변수 값을 변경하면 모든 작업의 ​​해시가 변경됩니다.
- **env**: 작업에 영향을 미치는 환경 변수 값에 대한 변경 사항을 포함하여 더 나은 세부성을 허용합니다. 예를 들어 `lint` 작업은 `API_KEY` 값이 변경될 때 캐시를 놓칠 필요가 없지만 `build` 작업은 캐시를 놓칠 가능성이 높습니다.

<Callout type="info">
  Turborepo는 환경 변수에 대한 와일드카드를 지원하므로 쉽게
 주어진 접두사가 있는 모든 환경 변수를 고려합니다. [API를 방문하세요.
 자세한 내용은 `env` 참조](/docs/reference/configuration#wildcards)를 참조하세요.
</Callout>

### 프레임워크 추론

Turborepo는 공통 프레임워크의 [`env`](/docs/reference/configuration#env) 키에 접두사 와일드카드를 자동으로 추가합니다. 패키지에서 아래 프레임워크 중 하나를 사용하는 경우 다음 접두사를 사용하여 환경 변수를 지정할 필요가 없습니다.

| 프레임워크 | `env` 와일드카드 |
| ---------------- | --------- |
| Next.js | `NEXT_PUBLIC_*` |
| VITE | `VITE_*` |
| React 앱 만들기 | `REACT_APP_*` |
| 개츠비 | `GATSBY_*` |
| 누스트 | `NUXT_*`, `NUXT_ENV_*` |
| 엑스포 | `EXPO_PUBLIC_*` |
| 아스트로 | `PUBLIC_*` |
| SvelteKit | `PUBLIC_*` |
| 리믹스 | `REMIX_*` |
| 솔리드스타트 | `VITE_*` |
| 레드우드JS | `REDWOOD_ENV_*` |
| 정신 | `SANITY_STUDIO_*` |

<Callout type="info">프레임워크 추론은 패키지별로 수행됩니다.</Callout>

프레임워크 추론을 선택 해제하려면 다음을 수행하세요.

- `--framework-inference=false`으로 작업 실행
- `env` 키에 음수 와일드카드 추가(예: `"env": ["!NEXT_PUBLIC_*"]`)

## 환경 모드

Turborepo의 환경 모드를 사용하면 런타임 시 작업에 사용할 수 있는 환경 변수를 제어할 수 있습니다.

- [엄격 모드](#strict-mode)(기본값): `turbo.json`의 `env` 및 `globalEnv` 키에 지정된 환경 변수 **만** 필터링합니다.
- [느슨한 모드](#loose-mode): 프로세스의 모든 환경 변수를 사용할 수 있도록 허용합니다.

### 엄격 모드

엄격 모드는 작업 런타임에 사용할 수 있는 환경 변수를 `turbo.json`의 `globalEnv` 및 `env` 키에 지정된 환경 변수 **만** 필터링합니다.

즉, 필요한 모든 환경 변수를 설명하지 않는 작업은 실패할 가능성이 높습니다. 다른 환경에서 잠재적으로 다른 동작을 가질 수 있는 작업을 캐시하고 싶지 않기 때문에 이는 좋은 것입니다.

<Callout type="warn" title="엄격 모드를 통한 캐시 안전성">
  엄격 모드에서는 다음과 같은 경우 작업이 실패할 가능성이 훨씬 더 높습니다.
 모든 환경 변수를 고려하지 않았으므로 보장되지 않습니다.
 작업 실패. 애플리케이션이 누락된 항목을 정상적으로 처리할 수 있는 경우
 환경 변수를 사용해도 작업을 성공적으로 완료하고 얻을 수 있습니다.
 의도하지 않은 캐시 적중.
</Callout>

#### 통과 변수

고급 사용 사례에서는 일부 환경 변수를 만들고 싶을 수도 있습니다.
해시에 포함하지 않고 작업에 사용할 수 있습니다. 이러한 변수에 대한 변경 사항은 작업 출력에 영향을 미치지 않지만 작업을 성공적으로 실행하려면 계속 사용할 수 있어야 합니다.

이러한 경우 해당 환경 변수를 [`globalPassThroughEnv`](/docs/reference/configuration#globalpassthroughenv) 및 [`passThroughEnv`](/docs/reference/configuration#passthroughenv)에 추가하세요.

#### CI 공급업체 호환성

엄격 모드는 [`env`](/docs/reference/configuration#env), [`globalEnv`](/docs/reference/configuration#globalenv), [`passThroughEnv`](/docs/reference/configuration#passthroughenv) 또는 [`globalPassThroughEnv`](/docs/reference/configuration#globalpassthroughenv).

이러한 변수 중 작업에 중요하고 [프레임워크 추론](#framework-inference)에 포함되지 않은 변수가 `turbo.json` 구성에 있는지 확인하세요.

### 루즈 모드

느슨한 모드는 `globalEnv` 및 `env` 키에 따라 환경 변수를 필터링하지 않습니다. 이렇게 하면 엄격 모드로 점진적으로 마이그레이션을 시작하기가 더 쉬워집니다.

스크립트에서 환경 변수를 찾을 수 없는 모든 호출에서 느슨한 모드를 활성화하려면 [`--env-mode` 플래그](/docs/reference/run#--env-mode-option)를 사용하세요.

```bash title="Terminal"
turbo run build --env-mode=loose
```

`turbo`이 실행될 때 환경 변수를 사용할 수 있는 한 스크립트에서 이를 사용할 수 있습니다. 그러나 이렇게 하면 **실수로 구성에서 환경 변수를 고려하는 것을 훨씬 더 쉽게 잊어버릴 수 있으며** 작업이 캐시에 적중되지 않아야 할 때 캐시에 적중할 수 있습니다.

예를 들어, 기본 URL에 대한 환경 변수를 사용하여 API에서 데이터를 가져오는 일부 코드가 애플리케이션에 있을 수 있습니다.

```ts title="./apps/web/data-fetcher.ts"
const data = fetch(`${process.env.MY_API_URL}/resource/1`);
```

그런 다음 미리 보기 환경을 대상으로 하는 `MY_API_URL` 값을 사용하여 애플리케이션을 빌드합니다. 애플리케이션을 출시할 준비가 되면 프로덕션용으로 빌드하고 `MY_API_URL` 변수의 값이 변경되었음에도 불구하고 캐시 적중을 확인합니다. `MY_API_URL` 변경됨 - Turborepo는 프로덕션 환경이 아닌 미리보기 환경의 `MY_API_URL`을 사용하는 캐시에서 애플리케이션 버전을 복원했습니다.

느슨한 모드를 사용하는 경우 **작업 해시에서 고려되지 않더라도** 작업 런타임에서 `MY_API_URL`을 사용할 수 있습니다. 이 작업이 실패할 가능성을 높이고 잘못된 구성으로부터 사용자를 보호하려면 [엄격 모드](#strict-mode)를 선택하는 것이 좋습니다.

### 플랫폼 환경 변수

애플리케이션을 [Vercel](https://vercel.com/new?ref=turborepo)에 배포할 때 프로젝트에 이미 [환경 변수](https://vercel.com/docs/projects/environment-variables)가 구성되어 있을 가능성이 높습니다. Turborepo는 `turbo.json` 구성에 대해 이러한 변수를 자동으로 확인하여 [이를 고려했는지](#adding-environment-variables-to-task-hashes) 확인합니다.
누락된 변수에 대해 경고합니다.

이 기능은 `TURBO_PLATFORM_ENV_DISABLED=false`을 설정하여 비활성화할 수 있습니다.

## `.env` 파일 처리

`.env` 파일은 로컬에서 애플리케이션을 작업하는 데 적합합니다. **Turborepo는 .env 파일을 작업 런타임에 로드하지 않으므로** 해당 파일은 프레임워크나 [`dotenv`](https://www.npmjs.com/package/dotenv)와 같은 도구에서 처리되도록 둡니다.

그러나 `turbo`이 `.env` 파일의 값 변경 사항을 알고 이를 해싱에 사용할 수 있도록 하는 것이 중요합니다. 빌드 간에 `.env` 파일의 변수를 변경하면 `build` 작업에서 캐시가 누락됩니다.

이렇게 하려면 [`inputs`](/docs/reference/configuration#inputs) 키에 파일을 추가하세요.

```json title="./turbo.json"
{
  "globalDependencies": [".env"], // All task hashes
  "tasks": {
    "build": {
      "inputs": ["$TURBO_DEFAULT$", ".env"] // Only the `build` task hash
    }
  }
}
```

### 여러 개의 `.env` 파일

`*`을 사용하여 여러 개의 `.env` 파일을 한 번에 캡처할 수 있습니다.

```json title="./turbo.json"
{
  "globalDependencies": [".env"], // All task hashes
  "tasks": {
    "build": {
      "inputs": ["$TURBO_DEFAULT$", ".env*"] // Only the `build` task hash
    }
  }
}
```

<Callout type="info">
  `.env` 파일은 다음과 같은 경우에도 작업 런타임에 변수를 로드할 수 있습니다.
 환경 변수가 [`env`에 추가되지 않았습니다.
 키](/docs/reference/configuration#env). 환경을 추가했는지 확인하세요.
 빌드용 변수 CI 및 프로덕션 빌드용 `env` 키입니다.
</Callout>

## 모범 사례

### 애플리케이션 패키지에서 `.env` 파일 사용

저장소 루트에 `.env` 파일을 사용하는 것은 권장되지 않습니다. 대신 `.env` 파일을 해당 파일이 사용되는 [애플리케이션 패키지](/docs/core-concepts/package-types#application-packages)에 배치하는 것이 좋습니다.

환경 변수가 각 애플리케이션의 런타임에 개별적으로 존재하므로 이 방법을 사용하면 애플리케이션의 런타임 동작을 더욱 밀접하게 모델링할 수 있습니다. 또한, 모노레포가 확장됨에 따라 이 방법을 사용하면 각 애플리케이션의 환경을 더 쉽게 관리할 수 있어 애플리케이션 전체에서 환경 변수 누출을 ​​방지할 수 있습니다.

<Callout type="info">
  증분 마이그레이션 시 루트 `.env` 파일을 사용하는 것이 더 쉬울 수 있습니다.
 모노레포로. [dotenv](https://www.npmjs.com/package/dotenv)와 같은 도구는
 다른 위치에서 `.env` 파일을 로드합니다. 마이그레이션을 완료한 후에는 루트 `.env` 파일을 사용하지 않는 것을 목표로 하는 것이 좋습니다.
</Callout>

### `eslint-config-turbo` 사용

[`eslint-config-turbo` 패키지](/docs/reference/eslint-config-turbo)는 `turbo.json`에 나열되지 않은 코드에 사용되는 환경 변수를 찾는 데 도움이 됩니다. 이렇게 하면 모든 환경 변수가 구성에 고려되도록 하는 데 도움이 됩니다.

### 런타임 시 환경 변수 생성 또는 변경 방지

Turborepo는 작업 시작 시 작업에 대한 환경 변수를 해시합니다. 작업 중에 환경 변수를 생성하거나 변경하는 경우 Turborepo는 이러한 변경 사항을 알지 못하며 작업 해시에서 이를 설명하지 않습니다.

예를 들어 Turborepo는 아래 예에서 인라인 변수를 감지할 수 없습니다.

```json title="./apps/web/package.json"
{
  "scripts": {
    "dev": "export MY_VARIABLE=123 && next dev"
  }
}
```

`MY_VARIABLE`은 `dev` 작업이 시작된 후_ 환경에 추가되므로 `turbo`은 이를 해싱에 사용할 수 없습니다.
