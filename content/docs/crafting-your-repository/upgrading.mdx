## 2.0으로 업그레이드

<Steps>
<Step>

### 업데이트 `turbo.json`

다음을 실행하여 1.x에서 2.0으로 업그레이드를 시작하세요.

<PackageManagerTabs>

<Tab value="pnpm">

```bash title="Terminal"
pnpm dlx @turbo/codemod migrate
```

</Tab>

<Tab value="yarn">

```bash title="Terminal"
yarn dlx @turbo/codemod migrate
```

</Tab>

<Tab value="npm">

```bash title="Terminal"
npx @turbo/codemod migrate
```

</Tab>

<Tab value="bun">

```bash title="Terminal"
bunx @turbo/codemod migrate
```

</Tab>

</PackageManagerTabs>

이렇게 하면 1.x에서 2.0으로의 많은 주요 변경 사항에 대해 `turbo.json`(s)가 업데이트됩니다.

또한 `name` 필드가 작업 공간에 없는 `package.json`에 추가됩니다.

<Callout type="info">
  각 codemod를 개별적으로 수동으로 실행할 수도 있습니다. [codemods를 방문하세요.
 자세한 내용은 페이지](/docs/reference/turbo-codemod#turborepo-2x)를 참조하세요.
</Callout>

</Step>

<Step>

### 루트 `package.json`에 `packageManager` 필드 추가

[`packageManager` 필드](https://nodejs.org/api/packages.html#packagemanager)는 작업공간에서 사용될 것으로 예상되는 패키지 관리자를 정의하는 Node.js 생태계의 규칙입니다.

Turborepo 2.0에서는 코드베이스의 안정성과 동작 예측 가능성을 향상시키기 위한 방법으로 작업공간에서 이 필드를 정의해야 합니다. 아직 없는 경우 이 필드를 루트 `package.json`에 추가하세요.

<PackageManagerTabs>

<Tab value="pnpm">

```diff title="./package.json"
{
+ "packageManager": "pnpm@9.2.0"
}
```

</Tab>

<Tab value="yarn">

```diff title="./package.json"
{
+ "packageManager": "yarn@1.22.19"
}
```

</Tab>

<Tab value="npm">

```diff title="./package.json"
{
+ "packageManager": "npm@10.8.1"
}
```

</Tab>

<Tab value="bun">

```diff title="./package.json"
{
+ "packageManager": "bun@1.2.0"
}
```

</Tab>
</PackageManagerTabs>

</Step>
<Step>

### 업데이트 `eslint-config-turbo`

[`eslint-config-turbo`](/docs/reference/eslint-config-turbo)는 캐싱을 위해 [`env`](/docs/reference/configuration#env) 키에 추가해야 하는 환경 변수를 식별하는 데 도움이 됩니다. 이를 사용하는 경우 주요 버전과 일치하도록 업데이트했는지 확인하세요.

</Step>

<Step>

### `turbo run` 명령 업데이트

Turborepo 2.0에는 `turbo run` 명령의 동작에 대한 동작 및 정확성 개선 사항이 포함되어 있습니다. 아래 목록은 코드베이스에 영향을 미칠 수도 있고 그렇지 않을 수도 있는 변경 사항을 요약한 것입니다.

- 환경 변수에 대한 엄격한 모드가 이제 기본값이며, 느슨한 모드에서 이동합니다([홍보](https://github.com/vercel/turborepo/pull/8182)).
 - 작업의 스크립트에 환경 변수가 누락된 것으로 나타나면 명령별로 [`--env-mode` 옵션](/docs/reference/run#--env-mode-option)을 사용하여 이 동작을 취소하여 점진적으로 마이그레이션할 수 있습니다. 가능한 한 빨리 `--env-mode` 옵션을 삭제할 수 있도록 모든 환경 변수를 고려하여 작업에서 [`env` 키](/docs/reference/configuration#env)를 업데이트하는 것이 좋습니다.
 - 저장소의 기본값을 다시 느슨한 모드로 설정하려면 [`envMode` 구성을 사용하여](/docs/reference/configuration#envmode) 그렇게 할 수 있습니다.
- 작업공간 루트 디렉토리는 이제 모든 패키지의 암시적 종속성입니다([홍보](https://github.com/vercel/turborepo/pull/8202)).
 - 루트에 대한 변경 사항은 저장소의 모든 작업에 영향을 미칠 수 있으므로 저장소의 루트에는 가능한 한 적은 코드가 있어야 합니다. 또한 작업공간 루트에서 [내부 패키지](/docs/core-concepts/internal-packages)를 사용하는 경우 해당 종속성을 변경하면 모든 작업에서 캐시 누락이 발생합니다. 두 경우 모두 코드를 루트에서 [패키지로](/docs/crafting-your-repository/structuring-a-repository) 이동하는 것이 좋습니다.
- `--ignore`이(가) 삭제되고 `--filter`이 변경되었으며 아래 그래프 정확성이 변경되었습니다([홍보](https://github.com/vercel/turborepo/pull/8201)).
- `--scope` 플래그 제거(1.2부터 더 이상 사용되지 않음) ([홍보](https://github.com/vercel/turborepo/pull/7970))
- 루트 `package.json`의 `engines` 필드가 이제 해싱에 사용됩니다([홍보](https://github.com/vercel/turborepo/pull/8173)).
- `--filter`은 더 이상 패키지 이름에 대한 네임스페이스를 유추하지 않습니다([홍보](https://github.com/vercel/turborepo/pull/8137)).
- 이제 패키지 이름이나 디렉터리가 일치하지 않으면 `--filter` 오류가 발생합니다([홍보](https://github.com/vercel/turborepo/pull/8142)).
- `--only`은 패키지 종속성 대신 작업 종속성을 제한합니다([홍보](https://github.com/vercel/turborepo/pull/8163)).

</Step>
</Steps>
