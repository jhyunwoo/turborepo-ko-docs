Turborepo는 작업을 자동으로 병렬화하고 캐싱하여 저장소의 개발자 워크플로를 최적화합니다. 작업이 [`turbo.json`에 등록되면](/docs/crafting-your-repository/configuring-tasks) 저장소에서 스크립트를 실행하기 위한 강력한 새 도구 세트를 갖게 됩니다.

- [자주 실행해야 하는 작업에는 `package.json`의 `scripts`을 사용하세요](#using-scripts-in-packagejson)
- [글로벌 `turbo`을 사용하여 주문형 사용자 지정 작업을 빠르게 실행](#using-global-turbo)
- [디렉터리, 패키지 이름, 소스 제어 변경 사항 등을 기준으로 작업 필터링](#using-filters)

`turbo`을 통한 작업 실행은 개발 시 리포지토리 전체와 CI 파이프라인에서 워크플로를 실행하기 위한 단일 모델을 얻을 수 있기 때문에 강력합니다.

## `package.json`에서 `scripts` 사용

자주 실행하는 작업의 경우 `turbo` 명령을 루트 `package.json`에 직접 작성할 수 있습니다.

```jsonc title="./package.json"
{
  "scripts": {
    "dev": "turbo run dev",
    "build": "turbo run build",
    "test": "turbo run test",
    "lint": "turbo run lint"
  }
}
```

<Callout type="info">
  `turbo`은 `turbo run`의 별칭입니다. 하지만 `turbo run`을 사용하는 것이 좋습니다.
 잠재적인 충돌을 방지하기 위한 `package.json` 및 CI 워크플로
 `turbo` 향후 추가될 수 있는 하위 명령입니다.
</Callout>

그런 다음 패키지 관리자를 사용하여 이러한 스크립트를 실행할 수 있습니다.

<PackageManagerTabs>

  <Tab value="pnpm">
  ```bash title="단말기"
 pnpm dev
 ```

  </Tab>

  <Tab value="yarn">

```bash title="Terminal"
yarn dev
```

  </Tab>

  <Tab value="npm">

```bash title="Terminal"
npm run dev
```

  </Tab>

  <Tab value="bun">

```bash title="Terminal"
bun run dev
```

  </Tab>
</PackageManagerTabs>

<Callout type="warn">
`package.json` 루트에만 `turbo` 명령을 작성하려고 합니다. `turbo` 명령을 패키지의 `package.json`에 쓰면 재귀적으로 오류가 발생할 수 있습니다.
`turbo`에 전화를 걸고 있습니다.

</Callout>

## 전역 `turbo` 사용

[`turbo` 전역 설치](/docs/getting-started/installation#global-installation)를 사용하면 터미널에서 직접 명령을 실행할 수 있습니다. 이를 통해 필요할 때 필요한 것을 정확하게 실행할 수 있으므로 로컬 개발 경험이 향상됩니다.

또한 글로벌 `turbo`은 CI 파이프라인에 유용하므로 파이프라인의 각 지점에서 실행할 작업을 정확하게 제어할 수 있습니다.

### 자동 패키지 범위 지정

패키지 디렉터리에 있을 때 `turbo`은 명령 범위를 해당 패키지의 [패키지 그래프](/docs/core-concepts/package-and-task-graph#package-graph)로 자동 지정합니다. 즉, 패키지에 대해 [필터 작성](/docs/reference/run#--filter-string)하지 않고도 명령을 빠르게 작성할 수 있습니다.

```bash title="Terminal"
cd apps/docs
turbo build
```

위의 예에서 `turbo build` 명령은 `turbo.json`에 등록된 `build` 작업을 사용하여 `docs` 패키지에 대한 `build` 작업을 실행합니다.

<Callout type="info">
  [필터 사용](#using-filters)은 자동 패키지 범위 지정을 재정의합니다.
</Callout>

### 동작 맞춤설정

[`run` 하위 명령에 대한 문서](/docs/reference/run)에서는 필요한 것에 맞게 `turbo run`의 동작을 조정하는 데 유용한 많은 플래그를 찾을 수 있습니다. 전역 `turbo`을 실행할 때 다음과 같은 워크플로를 사용하면 더 빠르게 진행할 수 있습니다.

- **가장 일반적인 명령의 변형**: `package.json`의 `build` 스크립트는 `turbo build`일 때 가장 유용합니다. 하지만 현재로서는 특정 패키지에만 관심이 있을 수 있습니다. `turbo build --filter=@repo/ui`을 사용하여 관심 있는 특정 패키지를 빠르게 필터링할 수 있습니다.
- **일회성 명령**: `turbo build --dry`과 같은 명령은 자주 필요하지 않으므로 `package.json`에 스크립트를 만들지 않을 것입니다. 대신 필요할 때마다 터미널에서 직접 실행할 수 있습니다.
- **`turbo.json` 구성 재정의**: 일부 CLI 플래그에는 재정의할 수 있는 `turbo.json`에 해당하는 플래그가 있습니다. 예를 들어, [`"outputLogs": "full"` in `turbo.json`](/docs/reference/configuration#outputlogs)을 사용하도록 구성된 `turbo build` 명령이 있을 수 있지만 현재는 오류 확인에만 관심이 있습니다. 전역 `turbo`을 사용하면 `turbo lint --output-logs=errors-only`을 사용하여 오류만 표시할 수 있습니다.

## 여러 작업 실행

`turbo`은 가능할 때마다 병렬화하여 여러 작업을 실행할 수 있습니다.

```bash title="Terminal"
turbo run build test lint check-types
```

이 명령은 모든 작업을 실행하여 작업 정의에 따라 가능한 한 빨리 스크립트를 실행할 수 있는 위치를 자동으로 감지합니다.

<Callout type="info" title="작업 순서">
`turbo test lint`은 `turbo lint test`과 정확히 동일한 작업을 실행합니다.

한 작업이 다른 작업의 실행을 차단하도록 하려면 [작업 구성](/docs/crafting-your-repository/configuring-tasks#defining-tasks)에서 해당 관계를 표현하세요.

</Callout>

## 필터 사용하기

[캐싱](/docs/crafting-your-repository/running-tasks)을 사용하면 동일한 작업을 두 번 수행하지 않아 속도를 유지할 수 있지만 [작업 그래프](/docs/core-concepts/package-and-task-graph#task-graph)의 하위 집합만 실행하도록 작업을 필터링할 수도 있습니다.

[`--filter` API 참조](/docs/reference/run#--filter-string)에는 필터링에 대한 고급 사용 사례가 많이 있지만 가장 일반적인 사용 사례는 아래에 설명되어 있습니다.

### 패키지로 필터링

패키지별 필터링은 현재 작업 중인 패키지에 대한 작업만 실행하는 간단한 방법입니다.

```bash title="Terminal"
turbo build --filter=@acme/web
```

<InVersion version="2.2.4">

`--filter`을 사용할 필요 없이 CLI 명령에서 직접 패키지에 대한 특정 작업으로 필터링할 수도 있습니다.

```bash title="Terminal"
# `web` 패키지에 대해 `build` 작업 실행turbo run web#build

# `web` 패키지에 대해 `build` 작업을 실행하고 `docs` 패키지에 대해 `lint` 작업을 실행합니다.turbo run web#build docs#lint
```

</InVersion>

### 디렉토리별 필터링

저장소에는 관련 패키지가 함께 그룹화되는 디렉터리 구조가 있을 수 있습니다. 이 경우 해당 디렉터리에 대한 glob을 캡처하여 `turbo` 해당 패키지에 집중할 수 있습니다.

```bash title="Terminal"
turbo lint --filter="./packages/utilities/*"
```

### 부양가족을 포함하도록 필터링 중

특정 패키지에 대해 작업할 때 해당 패키지와 해당 종속 항목에 대한 작업을 실행해야 할 수 있습니다. `...` 마이크로 구문은 패키지를 변경하고 변경 사항으로 인해 종속 항목이 중단되지 않도록 하려는 경우에 유용합니다.

```bash title="Terminal"
turbo build --filter=...ui
```

### 종속성을 포함하도록 필터링

범위를 패키지 및 해당 종속성으로 제한하려면 패키지 이름에 `...`을 추가하세요. 그러면 지정된 패키지와 해당 패키지가 종속된 모든 패키지에 대한 작업이 실행됩니다.

```bash title="Terminal"
turbo dev --filter=web...
```

### 소스 제어 변경으로 필터링

필터를 사용하여 소스 제어의 변경 사항에 따라 작업을 실행하는 것은 변경 사항의 영향을 받는 패키지에 대해서만 작업을 실행하는 좋은 방법입니다. **소스 제어 필터는 `[]`**로 래핑되어야 합니다.

- **이전 커밋과 비교**: `turbo build --filter=[HEAD^1]`
- **본점 대비**: `turbo build --filter=[main...my-feature]`
- **SHA를 사용하여 특정 커밋 비교**: `turbo build --filter=[a1b2c3d...e4f5g6h]`
- **브랜치 이름을 사용하여 특정 커밋 비교**: `turbo build --filter=[your-feature...my-feature]`

<Callout type="info">
  일반적으로 캐싱을 사용하여 저장소를 빠르게 유지할 수 있습니다. 당신이 언제
 [원격 캐싱](/docs/core-concepts/remote-caching)을 사용하면 믿을 수 있습니다.
 변경되지 않은 패키지에 대해 캐시를 적중합니다.
</Callout>

### 필터 결합

더욱 구체적으로 만들기 위해 필터를 결합하여 [작업 그래프](/docs/core-concepts/package-and-task-graph#task-graph)의 진입점을 더욱 구체화할 수 있습니다.

```bash title="Terminal"
turbo build --filter=...ui --filter={./packages/*} --filter=[HEAD^1]
```

여러 필터가 **통합**으로 결합됩니다. 즉, [작업 그래프](/docs/core-concepts/package-and-task-graph#task-graph)에는 필터 중 하나와 일치하는 작업이 포함됩니다. 필터의 고급 사용에 대한 자세한 내용은 [`--filter` API 참조](/docs/reference/run#--filter-string)를 참조하세요.
