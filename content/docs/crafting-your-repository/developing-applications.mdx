모노레포에서 애플리케이션을 개발하면 강력한 워크플로가 잠금 해제되어 코드에 쉽게 액세스하여 소스 제어에 대한 원자성 커밋을 수행할 수 있습니다.

대부분의 개발 작업은 코드 변경 사항을 감시하는 장기 실행 작업입니다. Turborepo는 강력한 터미널 UI와 다음과 같은 기타 기능을 통해 이러한 경험을 향상시킵니다.

- [시계 모드](#watch-mode)
- [설정 스크립트 실행](#running-setup-tasks-before-dev)
- [패키지의 하위 집합을 실행하기 위한 작업 필터링](#running-a-specific-application)

## 개발 작업 구성

`turbo.json`에서 개발 작업을 정의하면 Turborepo에 수명이 긴 작업이 실행될 것임을 알립니다. 이는 개발 서버 실행, 테스트 실행, 애플리케이션 구축 등에 유용합니다.

`dev` 작업을 등록하려면 두 가지 속성을 사용하여 `turbo.json`에 추가하세요.

```json title="./turbo.json"
{
  "tasks": {
    "dev": {
      "cache": false,
      "persistent": true
    }
  }
}
```

- **"cache": false**: Turborepo에 작업 결과를 캐시하려고 시도하지 않도록 지시합니다. 이는 개발 작업이므로 코드를 자주 변경하게 되므로 결과를 캐싱하는 것은 유용하지 않습니다.
- **"지속적": true**: 중지할 때까지 작업을 계속 실행하도록 Turborepo에 지시합니다. 이 키는 작업을 장기 실행 및 대화형 작업으로 처리하도록 터미널 UI에 대한 신호 역할을 합니다. 또한 종료되지 않는 작업에 실수로 의존하는 것을 방지합니다.

이제 `dev` 작업을 실행하여 개발 스크립트를 병렬로 시작할 수 있습니다.

```bash title="Terminal"
turbo dev
```

### `dev` 이전에 설정 작업 실행

개발 환경을 설정하거나 패키지를 사전 빌드하는 스크립트를 실행할 수도 있습니다. `dependsOn`을 사용하여 `dev` 작업 전에 해당 작업이 실행되도록 할 수 있습니다.

```json title="./turbo.json"
{
  "tasks": {
    "dev": {
      "cache": false,
      "persistent": true,
      "dependsOn": ["//#dev:setup"]
    },
    "//#dev:setup": {
      "outputs": [".codegen/**"]
    }
  }
}
```

이 예에서는 [루트 작업](/docs/crafting-your-repository/configuring-tasks#registering-root-tasks)을 사용하지만 [패키지의 임의 작업](/docs/crafting-your-repository/configuring-tasks#depending-on-a-specific-task-in-a-specific-package)에도 동일한 아이디어를 사용할 수 있습니다.

### 특정 애플리케이션 실행

`--filter` 플래그를 사용하면 [패키지 그래프](/docs/core-concepts/package-and-task-graph#package-graph)의 하위 집합을 선택할 수 있으므로 특정 애플리케이션 및 해당 종속성에 대해 `dev` 작업을 실행할 수 있습니다.

```bash title="Terminal"
turbo dev --filter=web
```

## 터미널 UI 사용하기

Turborepo의 터미널 UI는 작업에 대한 고도의 대화형 경험을 생성하는 다양한 기능을 활성화합니다.

### 보기 맞춤설정

키 바인딩을 사용하여 필요에 맞게 UI를 빠르게 조정할 수 있습니다.

| 키바인드 | 액션 |
| ------- | ----------------------------------------------------------------- |
| `m` | 팝업 목록 키 바인드 전환 |
| `↑`/`↓` | 작업 목록에서 다음/이전 작업 선택 |
| `j`/`k` | 작업 목록에서 다음/이전 작업 선택 |
| `p` | 선택한 작업에 대한 선택 고정 전환 |
| `h` | 작업 목록 표시 여부 전환 |
| `c` | 로그가 강조 표시되면 선택 항목을 시스템 클립보드에 복사 |
| `u`/`d` | 스크롤 로그 `u`p 및 `d`own |

### 작업과 상호작용

일부 도구에서는 입력을 입력할 수 있습니다. 이에 대한 예로는 Drizzle ORM의 대화형 마이그레이션 또는 Jest의 테스트 스위트 필터링 및 재실행이 있습니다.

[대화형으로 표시](/docs/reference/configuration#interactive)된 작업과 상호작용하여 입력을 제공할 수 있습니다.

| 키바인드 | 액션 |
| -------- | ----------------- |
| `i` | 상호작용 시작 |
| `Ctrl+z` | 상호작용을 중지하세요 |

## 시청 모드

[`tsc --watch`](https://www.typescriptlang.org/docs/handbook/compiler-options.html#compiler-options)과 같은 많은 도구에는 감시자가 내장되어 있습니다.
소스 코드의 변경 사항에 응답합니다. 그러나 일부는 그렇지 않습니다.

`turbo watch`은 모든 도구에 종속성 인식 감시자를 추가합니다. 소스 코드에 대한 변경 사항은 다른 모든 작업과 마찬가지로 `turbo.json`에 설명된 [작업 그래프](/docs/core-concepts/package-and-task-graph#task-graph)를 따릅니다.

예를 들어, 다음 작업 및 스크립트와 함께 [`create-turbo`](/docs/reference/create-turbo)와 같은 패키지 구조를 사용합니다.

<Tabs items={["turbo.json", "packages/ui", "apps/web"]}>
<Tab value="turbo.json">

```json title="turbo.json"
{
  "tasks": {
    "dev": {
      "persistent": true,
      "cache": false
    },
    "lint": {
      "dependsOn": ["^lint"]
    }
  }
}
```

</Tab>

<Tab value="packages/ui">

```json title="package.json"
{
  "name": "@repo/ui"
  "scripts": {
    "dev": "tsc --watch",
    "lint": "eslint ."
  }
}
```

</Tab>

<Tab value="apps/web">

```json title="package.json"
{
  "name": "web"
  "scripts": {
    "dev": "next dev",
    "lint": "eslint ."
  },
  "dependencies": {
      "@repo/ui": "workspace:*"
    }
}
```

</Tab>
</Tabs>

`turbo watch dev lint`을 실행하면 ESLint에 내장 감시자가 없음에도 불구하고 소스 코드를 변경할 때마다 `lint` 스크립트가 다시 실행되는 것을 볼 수 있습니다. `turbo watch`은 내부 종속성도 인식하므로 `@repo/ui`의 코드 변경으로 `@repo/ui` 및 `web` 모두에서 작업이 다시 실행됩니다.

`web`의 Next.js 개발 서버와 `@repo/ui`의 TypeScript 컴파일러 내장 감시자는 `persistent`로 표시되므로 평소대로 계속 작동합니다.

자세한 내용은 [`turbo watch` 참조를 방문하세요](/docs/reference/watch).

## 제한사항

### 분해 작업

어떤 경우에는 `dev` 작업이 중지될 때 스크립트를 실행해야 할 수도 있습니다. `dev` 작업이 종료될 때 `turbo`이 종료되기 때문에 Turborepo는 종료 시 해당 해체 스크립트를 실행할 수 없습니다.

대신 기본 `turbo dev` 작업을 종료한 후 별도로 실행하는 `turbo dev:teardown` 스크립트를 만드세요.
