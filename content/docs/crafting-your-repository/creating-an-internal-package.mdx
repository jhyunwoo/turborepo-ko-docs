[내부 패키지](/docs/core-concepts/internal-packages)는 워크스페이스의 구성 요소이며, 저장소 전체에서 코드와 기능을 공유할 수 있는 강력한 방법을 제공합니다. Turborepo는 `package.json`의 의존성을 사용해 내부 패키지 사이의 관계를 자동으로 이해하고, 내부적으로 [패키지 그래프](/docs/core-concepts/package-and-task-graph#package-graph)를 만들어 저장소의 워크플로를 최적화합니다.

![Turborepo의 패키지 그래프를 시각적으로 표현한 이미지입니다.](/images/docs/package-graph.png)

[패키지의 구조](/docs/crafting-your-repository/structuring-a-repository#anatomy-of-a-package) 섹션의 안내와 [컴파일된 패키지](/docs/core-concepts/internal-packages#compiled-packages) 패턴을 참고해, 저장소에서 수학 유틸리티를 공유하기 위한 첫 번째 내부 패키지를 만들어 보겠습니다. 아래 단계에서는 [`create-turbo`로 새 저장소를 만들었거나](/docs/getting-started/installation) 비슷한 구조의 저장소를 사용하고 있다고 가정합니다.

<Steps>
<Step>
### 빈 디렉터리 만들기

패키지를 넣을 디렉터리가 필요합니다. `./packages/math`에 디렉터리를 만들어 봅시다.

</Step>
<Step>
### `package.json` 추가하기

다음으로 패키지의 `package.json`을 만듭니다. 이 파일을 추가하면 [내부 패키지의 두 가지 요구 사항](/docs/crafting-your-repository/structuring-a-repository#specifying-packages-in-a-monorepo)을 충족하게 되어 Turborepo와 워크스페이스의 다른 도구들이 이 패키지를 발견할 수 있게 됩니다.

<Callout type="warn">
  `package.json`의 `name` 필드는 워크스페이스 전체에서 패키지를 어떻게
  import할지 결정합니다. 여기서 선택한 이름(예: `@repo/math`)이 다른
  패키지에서 이 패키지를 import하는 정확한 방식이 됩니다(예: `import {add}
  from '@repo/math/add'`).
</Callout>

이 `package.json`을 항목별로 살펴보겠습니다.

- **`name`**: 패키지를 찾을 수 있게 만드는 데 가장 중요한 필드입니다. `@repo/math` 값은 워크스페이스 전반의 import 문에서 사용되는 정확한 식별자가 됩니다. 이 이름을 바꾸면 모든 import 문도 함께 업데이트해야 합니다.
- **`scripts`**: `dev`와 `build` 스크립트는 [TypeScript 컴파일러](https://www.typescriptlang.org/docs/handbook/compiler-options.html)를 사용해 패키지를 컴파일합니다. `dev` 스크립트는 소스 코드 변경을 감시하고 패키지를 자동으로 다시 컴파일합니다.
- **`devDependencies`**: `typescript`와 `@repo/typescript-config`는 `devDependencies`에 들어 있으므로 `@repo/math` 패키지에서 사용할 수 있습니다. 실제 패키지에서는 더 많은 `devDependencies`와 `dependencies`가 있을 수 있지만, 지금은 단순하게 유지하겠습니다.
- **`exports`**: 패키지에 여러 엔트리포인트를 정의해 다른 패키지에서 사용할 수 있게 해 줍니다(`import { add } from '@repo/math/add'`).

특히 이 `package.json`은 내부 패키지인 `@repo/typescript-config`를 의존성으로 선언합니다. Turborepo는 작업 순서를 정할 때 `@repo/math`를 `@repo/typescript-config`에 의존하는 패키지로 인식합니다.

</Step>

<Step>
  ### `tsconfig.json` 추가하기

패키지의 **루트 디렉터리**에 `tsconfig.json` 파일을 추가해 이 패키지의 TypeScript 설정을 지정합니다. TypeScript에는 [`extends` 키](https://www.typescriptlang.org/tsconfig#extends)가 있어서 저장소 전체에서 기본 설정을 재사용하고, 필요에 따라 다른 옵션으로 덮어쓸 수 있습니다.

```json title="./packages/math/tsconfig.json"
{
  "extends": "@repo/typescript-config/base.json",
  "compilerOptions": {
    "outDir": "dist",
    "rootDir": "src"
  },
  "include": ["src"],
  "exclude": ["node_modules", "dist"]
}
```

여기서는 네 가지 중요한 작업을 했습니다.

- `./packages/typescript-config`에 있는 `@repo/typescript-config/base.json` 설정에는 필요한 구성이 이미 들어 있으므로 이를 확장합니다.
- `compilerOptions`의 [`outDir` 키](https://www.typescriptlang.org/tsconfig/#outDir)는 TypeScript에 컴파일된 출력을 어디에 둘지 알려 줍니다. 이 경로는 `package.json`의 `exports`에 지정한 디렉터리와 일치합니다.
- [`compilerOptions`의 `rootDir` 키](https://www.typescriptlang.org/tsconfig/#rootDir)는 `outDir`에 생성되는 출력이 `src` 디렉터리와 같은 구조를 사용하도록 보장합니다.
- [`include`](https://www.typescriptlang.org/tsconfig/#include)와 [`exclude`](https://www.typescriptlang.org/tsconfig/#exclude) 키는 [TypeScript 명세에 따라](https://www.typescriptlang.org/tsconfig#include) 기본 설정에서 상속되지 않으므로 여기에서 직접 포함했습니다.

<Callout type="info">
  TypeScript 설정에서 배울 것은 더 많지만, 지금 시작하기에는 이것이 좋은
  출발점입니다. 더 알아보고 싶다면 [공식 TypeScript
  문서](https://www.typescriptlang.org/tsconfig)나 [Turborepo의 TypeScript
  가이드](/docs/guides/tools/typescript)를 참고하세요.
</Callout>

</Step>

<Step>
### 소스 코드가 들어 있는 `src` 디렉터리 추가하기

이제 패키지 코드를 작성할 수 있습니다. `src` 디렉터리 안에 두 개의 파일을 만듭니다.

<Tabs items={['add.ts', 'subtract.ts']}>
  <Tab value="add.ts">

    ```ts title="./packages/math/src/add.ts"
    export const add = (a: number, b: number) => a + b;
    ```

  </Tab>
  <Tab value="subtract.ts">

    ```ts title="./packages/math/src/subtract.ts"
    export const subtract = (a: number, b: number) => a - b;
    ```

  </Tab>
</Tabs>

이 파일들은 잠시 뒤 `turbo build`를 실행할 때 `tsc`가 생성하는 출력과 대응됩니다.

</Step>

이제 `@repo/math`를 `web` 애플리케이션에서 사용할 수 있으므로 코드에서 다음처럼 활용할 수 있습니다.

```tsx title="apps/web/src/app/page.tsx"
import { add } from "@repo/math/add";

function Page() {
  return <div>{add(1, 2)}</div>;
}

export default Page;
```

<Step>
### `turbo.json` 수정하기

`turbo.json`의 `build` 작업에 있는 `outputs`에 새 `@repo/math` 라이브러리의 아티팩트를 추가합니다. 이렇게 하면 해당 빌드 출력이 Turborepo에 의해 캐시되어, 빌드를 실행할 때 즉시 복원할 수 있습니다.

```json title="./turbo.json"
// [!code word:"dist/**"]
{
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": [".next/**", "!.next/cache/**", "dist/**"]
    }
  }
}
```

</Step>

<Step>
### `turbo build` 실행하기

[`turbo`를 전역으로 설치했다면](/docs/getting-started/installation#global-installation) 워크스페이스 루트의 터미널에서 `turbo build`를 실행하세요. 패키지 매니저로 `package.json`의 `build` 스크립트를 실행해도 되며, 이 경우 내부적으로 `turbo run build`가 사용됩니다.

`web` 애플리케이션이 빌드되기 전에 `@repo/math` 패키지가 먼저 빌드되므로, 번들링 시 `./packages/math/dist`에 있는 런타임 코드를 `web` 애플리케이션이 사용할 수 있습니다.

<Callout type="info">
  `turbo build`를 다시 실행해 보면 `web` 애플리케이션이 **밀리초
  단위로** 다시 빌드되는 것을 확인할 수 있습니다. 이 부분은 [캐싱
  가이드](/docs/crafting-your-repository/caching)에서 자세히 다룹니다.
</Callout>

</Step>
</Steps>

## 내부 패키지를 위한 모범 사례

### 패키지마다 하나의 "목적"만 두기

내부 패키지를 만들 때는 하나의 "목적"을 가진 패키지를 만드는 것을 권장합니다. 이것은 엄격한 과학이나 규칙이라기보다, 저장소의 구조와 규모, 조직, 팀의 필요 등에 따라 달라지는 모범 사례입니다. 이 전략에는 몇 가지 장점이 있습니다.

- **이해하기 쉬움**: 저장소 규모가 커질수록, 저장소에서 작업하는 개발자가 필요한 코드를 더 쉽게 찾을 수 있습니다.
- **패키지별 의존성 줄이기**: 패키지마다 사용하는 의존성이 적을수록 Turborepo가 [패키지 그래프의 의존성을 정리](/docs/reference/prune)하는 작업을 더 효과적으로 수행할 수 있습니다.

예를 들면 다음과 같습니다.

- **`@repo/ui`**: 공유 UI 컴포넌트를 모두 담는 패키지
- **`@repo/tool-specific-config`**: 특정 도구의 설정을 관리하는 패키지
- **`@repo/graphs`**: 그래프 데이터를 생성하고 조작하기 위한 도메인 특화 라이브러리

### 애플리케이션 패키지에는 공유 코드가 들어가지 않는다

[애플리케이션 패키지](/docs/core-concepts/package-types#application-packages)를 만들 때는 공유 코드를 그 패키지 안에 넣지 않는 것이 좋습니다. 대신 공유 코드를 위한 별도의 패키지를 만들고, 애플리케이션 패키지가 그 패키지에 의존하도록 해야 합니다.

또한 애플리케이션 패키지는 다른 패키지에 설치하기 위한 용도가 아닙니다. 대신 [패키지 그래프](/docs/core-concepts/package-and-task-graph#package-graph)의 진입점으로 생각하는 것이 좋습니다.

<Callout type="info">
  이 규칙에는 [드문
  예외](/docs/core-concepts/package-types#installing-an-applicaiton-package-into-another-package)가
  있습니다.
</Callout>
