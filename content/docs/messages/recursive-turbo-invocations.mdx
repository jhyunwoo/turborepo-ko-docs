## 이 오류가 발생한 이유

[단일 패키지 작업공간](https://turborepo.dev/docs/guides/single-package-workspaces)에서 `turbo` 호출 주기가 감지되면 Turborepo는 자체에 대한 재귀 호출을 방지하기 위해 오류를 발생시킵니다. 일반적으로 이러한 상황은 다음 두 가지 이유 중 하나로 인해 발생합니다.

### 스크립트 및 작업의 재귀

단일 패키지 작업공간에서 동일한 이름의 Turborepo 작업을 호출하는 `package.json`의 스크립트로 인해 루프가 발생합니다.

```json title="./package.json"
{
  "scripts": {
    "build": "turbo run build"
  }
}
```

`build` 스크립트를 호출하면 `turbo run build`이 호출됩니다. 그런 다음 `turbo run build`는 `build` 스크립트를 호출하여 재귀 호출 루프를 시작합니다.

이 문제를 해결하려면 `package.json`의 스크립트 이름이 Turborepo 작업과 동일하지 않은지 확인하세요. 예를 들어 위의 코드 조각을 수정하려면 스크립트 이름을 바꾸면 주기가 중단됩니다.

```json title="./package.json"
{
  "scripts": {
    "build:app": "turbo run build"
  }
}
```

### 패키지 관리자 작업공간 구성 오류

잘못 구성된 작업공간으로 인해 [다중 패키지 작업공간](https://vercel.com/docs/vercel-platform/glossary#multi-package-workspace)이 단일 패키지 작업공간인 것처럼 보일 수 있습니다. 이로 인해 Turborepo는 저장소가 잘못된 유형이라고 추론하여 `package.json`의 스크립트가 재귀적으로 표시되도록 합니다.

저장소는 몇 가지 방법으로 이 상태로 끝날 수 있으며, 가장 일반적인 것은 [패키지가 패키지 관리자에 따라 정의되지 않음](https://turborepo.dev/docs/crafting-your-repository/structuring-a-repository#specifying-packages-in-a-monorepo)입니다. `package.json`에 `workspaces` 필드가 누락된 npm 작업 영역 또는 `pnpm-workspace.yaml` 파일이 누락된 pnpm 작업 영역에서 이 오류 메시지가 발생할 수 있습니다.

저장소가 다중 패키지 작업 영역에 대한 표준을 준수하는지 확인하고 문제를 수정하십시오.
