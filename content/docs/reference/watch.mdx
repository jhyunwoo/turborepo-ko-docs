코드 변경 사항에 따라 저장소에서 작업을 다시 실행하세요.

```bash title="Terminal"
turbo watch [tasks]
```

`turbo watch`은 종속성을 인식합니다. 즉, 작업이 [`turbo.json`에 구성된](/docs/reference/configuration) 순서대로 다시 실행됩니다.

작업이 제공되지 않으면 `turbo`은 저장소의 패키지에 사용할 수 있는 작업을 표시합니다.

```bash title="Terminal"
turbo watch
```

## 지속적인 작업에 `turbo watch` 사용

지속 작업은 [`"persistent": true`](/docs/reference/configuration#persistent)로 표시되어 종료되지 않음을 의미합니다. 이 때문에 작업 그래프에서는 의존할 수 없습니다.

이는 `turbo watch`을 사용할 때 지속 작업이 무시되고 [`turbo run`](/docs/reference/run)과 동일한 방식으로 작동하여 지속 작업과 비지속 작업이 동시에 실행될 수 있음을 의미합니다.

### 종속성 인식 영구 작업

스크립트에 종속성 변경 사항을 감지할 수 있는 내장 감시자(예: `next dev`)가 있는 경우 `turbo watch`을 사용할 필요가 없습니다. 대신 스크립트에 내장된 감시자를 사용하고 [`"persistent": true`](/docs/reference/configuration#persistent)을 사용하여 작업을 장기 실행으로 표시하세요.

### 종속성 인식 없이 지속되는 작업

일부 도구는 단일 저장소에 적합하지 않으며 종속성에서 모듈을 핫 리로드하지 않습니다. 그러한 경우에는 다음을 수행해야 합니다.
`turbo watch`을 가지려면 작업을 [`interruptible: true`](/docs/reference/configuration#interruptible)으로 표시하세요.
관련 변경 사항이 감지되면 작업을 다시 시작합니다.

## 제한사항

### 캐싱

감시 모드를 사용한 캐싱 작업은 현재 `--experimental-write-cache` 플래그 아래에서 실험적입니다.

```bash title="Terminal"
turbo watch your-tasks --experimental-write-cache
```

### 작업 출력

소스 제어에 체크인된 파일에 쓰는 작업이 있는 경우 감시 모드가 무한 루프에서 실행될 가능성이 있습니다. 이는 Watch Mode가 귀하의 정보를 감시하기 때문입니다.
파일을 변경하고 변경된 패키지의 작업을 다시 실행합니다. 작업이 변경을 생성하면 해당 작업이 다시 트리거됩니다.

감시 모드에는 파일 해시를 사용하여 이러한 일이 발생하지 않도록 방지하는 몇 가지 논리가 있지만 완벽하지는 않습니다. 이 문제를 방지하려면 git에서 작업 출력을 제거하는 것이 좋습니다.
