`turbo.json`에 지정된 작업을 실행합니다.

```bash title="Terminal"
turbo run [tasks] [options] [-- [args passed to tasks]]
```

<Callout type="info">
  `turbo run`은 `turbo`의 별칭입니다. `turbo run build lint check-types`는
  `turbo build lint check-types`와 같습니다. 사용 편의를 위해 CI 파이프라인에서는
  [`turbo run`을 사용](/docs/crafting-your-repository/constructing-ci#use-turbo-run-in-ci)하고,
  로컬에서는 [전역 `turbo`](/docs/getting-started/installation#global-installation)와 함께
  `turbo`를 사용하는 것을 권장합니다.
</Callout>

- **[작업]**: Turborepo는 동시에 하나 이상의 작업을 실행할 수 있습니다. `turbo`을 통해 작업을 실행하려면 `turbo.json`에 지정해야 합니다.
- **[옵션]**: 옵션은 `turbo run` 명령의 동작을 제어하는 ​​데 사용됩니다. 사용 가능한 플래그 옵션은 아래에 설명되어 있습니다.
- **[-- [작업에 전달된 인수]]**: 기본 스크립트에 인수를 전달할 수도 있습니다. 모든 인수는 실행 명령에 명명된 모든 작업에 전달됩니다.

<Callout type="info">
  Yarn v1을 사용하는 경우 작업에 인수를 전달하려면 `-- --`(이중 대시 두 세트)을 사용해야 합니다. `yarn turbo run build -- -- --sourcemap`. Yarn v1은 기본 스크립트에 인수를 전달하기 전에 첫 번째 `--`을 사용합니다.
</Callout>

작업이 제공되지 않으면 `turbo`은 저장소의 패키지에 사용할 수 있는 작업을 표시합니다.

```bash title="Terminal"
turbo run
```

## 옵션

### `--affected`

현재 분기의 변경 사항에 의해 영향을 받는 패키지만 필터링합니다.

```bash title="Terminal"
turbo run build lint test --affected
```

기본적으로 플래그는 `--filter=...[main...HEAD]`과 동일합니다. 이는 Git의 관점에서 `main`과 `HEAD` 사이의 변경 사항을 고려합니다.

<Callout type="warn">
  비교를 수행하려면 base와 head 사이의 모든 내용이 체크아웃에 존재해야 합니다.
  체크아웃이 너무 얕으면 모든 패키지가 변경된 것으로 간주됩니다.

예를 들어, `--filter=blob:none --depth=0`으로 체크아웃하도록 Git을 설정하면 `--affected`가 올바르게 작동하는 데 필요한 이력을 확보할 수 있습니다.

</Callout>

해당 [시스템 환경 변수](/docs/reference/system-environment-variables)를 사용하여 기본 베이스와 헤드를 재정의할 수 있습니다.

```bash title="Terminal"
# Git 비교 base 재정의
TURBO_SCM_BASE=development turbo run build --affected

# Git 비교 head 재정의
TURBO_SCM_HEAD=your-branch turbo run build --affected
```

### `--cache <options>`

기본값: `local:rw,remote:rw`

실행을 위한 캐싱 소스를 지정합니다. 쉼표로 구분된 옵션 목록을 허용합니다.

- `local`: 로컬 파일 시스템 캐시를 사용합니다.
- `remote`: 원격 캐시를 사용합니다.

캐싱 소스를 생략하면 읽기와 쓰기가 모두 비활성화됩니다.

캐시 소스는 다음 값을 사용합니다.

- `rw`: 읽고 쓰기
- `r`: 읽기 전용
- `w`: 쓰기 전용
- 없음(`local:`) : 캐시를 사용하지 않습니다. 캐시 소스 옵션을 생략하는 것과 동일합니다.

```bash title="Terminal"
# 로컬 캐시에서 읽고 씁니다. 원격 캐시에서는 읽기만 합니다.
turbo run build --cache=local:rw,remote:r

# 로컬 캐시에서는 읽기만 합니다. 원격 캐시에서는 읽고 씁니다.
turbo run build --cache=local:r,remote:rw

# 로컬 캐시에서 읽고 씁니다. 원격 캐시는 사용하지 않습니다.
turbo run build --cache=local:rw

# 로컬 캐시는 사용하지 않습니다. 원격 캐시에서는 읽기만 합니다.
turbo run build --cache=local:,remote:r
```

### `--cache-dir <path>`

기본값: `.turbo/cache`

파일 시스템 캐시 디렉터리를 지정합니다.

```bash title="Terminal"
turbo run build --cache-dir="./my-cache"
```

<Callout type="warn">
  변경할 때 디렉터리가 `.gitignore`에 있는지 확인하세요.
</Callout>

`TURBO_CACHE_DIR=example/path` 시스템 변수를 통해 동일한 동작을 설정할 수도 있습니다.

### `--concurrency <number | percentage>`

기본값: `10`

작업 실행을 위한 최대 동시성을 설정/제한합니다. `1`보다 크거나 같은 정수 또는 `50%`과 같은 백분율 값이어야 합니다.

- `1`을 사용하여 직렬 실행을 강제합니다(한 번에 하나의 작업).
- 사용 가능한 모든 논리 프로세서를 사용하려면 `100%`을 사용합니다.
- [`--parallel`](#--parallel) 플래그도 전달되면 이 옵션은 무시됩니다.

```bash title="Terminal"
turbo run build --concurrency=50%
turbo run test --concurrency=5
```

### `--continue[=<option>]`

기본값: `never`

오류가 있는 경우 `turbo`이 현재 및 보류 중인 작업을 처리하는 방법을 지정합니다(예: 작업의 0이 아닌 종료 코드).

- `--continue=never` 및 오류가 발생하면 `turbo`은 모든 작업을 취소합니다.
- `--continue=dependencies-successful` 및 오류가 발생하면 `turbo`은 종속 작업을 취소합니다. 종속성이 성공한 작업은 계속 실행됩니다.
- `--continue=always` 및 오류가 발생하면 `turbo`은 종속성이 실패한 작업을 포함하여 모든 작업을 계속 실행합니다.
- `--continue`을 값 없이 지정하면 기본값은 `always`입니다.

모든 경우에 `turbo`은 실행 중에 발견된 가장 높은 종료 코드 값으로 종료됩니다.

```bash title="Terminal"
turbo run build --continue
```

### `--cwd <path>`

기본값: 루트 `turbo.json`의 디렉터리

명령의 작업 디렉터리를 설정합니다.

```bash title="Terminal"
turbo run build --cwd=./somewhere/else/in/your/repo
```

### `--dangerously-disable-package-manager-check`

Turborepo는 저장소의 잠금 파일을 사용하여 캐싱 동작, [패키지 그래프](https://turborepo.dev/docs/core-concepts/internal-packages) 등을 결정합니다. 이 때문에 우리는 [`packageManager` 필드](https://nodejs.org/api/packages.html#packagemanager)를 사용하여 Turborepo를 안정화하는 데 도움을 줍니다.

증분 마이그레이션을 돕기 위해 또는 `packageManager` 필드를 사용할 수 없는 상황에서는 `--dangerously-disable-package-manager-check`을 사용하여 이 검사를 선택 해제하고 예측할 수 없는 동작을 생성하는 불안정한 잠금 파일의 위험을 감수할 수 있습니다. 비활성화되면 Turborepo는 저장소용으로 의도된 패키지 관리자를 찾기 위해 최선을 다합니다.

<Callout type="info">
  더 넓은 범위에 적용하려면
  [`turbo.json`의 구성](/docs/reference/configuration#dangerouslydisablepacakgemanagercheck)
  또는
  [`TURBO_DANGEROUSLY_DISABLE_PACKAGE_MANAGER_CHECK`](/docs/reference/system-environment-variables)
  환경 변수를 사용해 이 검사를 비활성화할 수도 있습니다.
</Callout>

### `--dry / --dry-run`

작업을 실행하는 대신 실행될 패키지 및 작업에 대한 세부 정보를 표시합니다.

JSON 형식으로 출력을 얻으려면 `--dry=json`을 지정합니다.

작업 세부정보에는 다음과 같은 유용한 정보가 포함됩니다(목록은 일부임).

| 필드 | 설명 |
| --------------- | --------------------------------------------------------- |
| `taskId` | `package-name#task-name` 형식의 작업 ID |
| `task` | 실행할 작업 이름 |
| `package` | 작업을 실행할 패키지 |
| `hash` | 작업 해시(캐싱에 사용됨) |
| `hashOfExternalDependencies` | 글로벌 해시 |
| `command` | 작업을 실행하는 데 사용되는 명령 |
| `inputs` | 해싱에 고려되는 파일 입력 목록 |
| `outputs` | 캐시된 파일 출력 목록 |
| `dependencies` | 이 작업 **전에** 실행해야 하는 작업 |
| `dependents` | 이 작업 **이후에** 실행해야 하는 작업 |
| `environmentVariables` | `env` 및 `passThroughEnv`에 지정된 환경 변수 목록 |

### `--env-mode <option>`

유형: `string`

작업 런타임에서 사용 가능한 환경 변수를 제어합니다.

<Callout type="info">
  `PATH`, `SHELL` 및 `SYSTEMROOT`은 항상 작업에 사용할 수 있습니다.
</Callout>

| 옵션 | 설명 |
| -------------- | ----------------------------------------------------- |
| [strict](#strict) (기본값) | 명시적으로 나열된 환경 변수만 사용 가능하도록 허용 |
| [loose](#loose) | **모든** 환경 변수를 사용할 수 있도록 허용 |

```bash title="Terminal"
turbo run build --env-mode=loose
```

`TURBO_ENV_MODE=strict` 시스템 변수를 통해 동일한 동작을 설정할 수도 있습니다.

#### `strict`

다음 키에 지정된 환경 변수만 작업에서 사용할 수 있습니다:

- [`env`](/docs/reference/configuration#env)
- [`passThroughEnv`](/docs/reference/configuration#passthroughenv)
- [`globalEnv`](/docs/reference/configuration#globalenv)
- [`globalPassThroughEnv`](/docs/reference/configuration#globalpassthroughenv)

`strict` 모드가 명시되거나 추론되면 구성과 관계없이 **모든** 작업이 `strict` 모드로 실행됩니다.

#### `loose`

머신의 모든 환경 변수는 작업 런타임에서 사용할 수 있습니다.

<Callout type="warn">
  이는 환경 변수가 위의 `strict`에 나열된 키를 통해 캐싱에 반영되지 않을 수 있으므로 위험할 수 있습니다.
  `loose` 모드에서는 잘못된 환경 변수를 가진 패키지 버전을 캐시에서 복원할 가능성이 훨씬 더 높습니다.
</Callout>

### `--filter <string>`

저장소의 그래프에서 실행할 대상을 지정하세요. 여러 필터를 결합하여 고유한 대상 집합을 선택할 수 있습니다.

필터를 결합하여 패키지, 디렉터리 및 git 커밋의 조합을 만들 수 있습니다.

| 대상 유형 | 설명 | 예 |
| ----------- | ------------------------------------------------------------------------------------------------ | ---------------------- |
| 패키지 | `package.json`의 이름으로 패키지를 선택합니다.                                      | `turbo run build --filter=ui` |
| 디렉토리 | 작업을 실행할 패키지 목록을 캡처하려면 디렉터리를 지정하세요. **다른 필터와 함께 사용하는 경우 `{}`**로 래핑해야 합니다. | `turbo run build --filter=./apps/*` |
| Git 커밋 | Git 지정자를 사용해 소스 제어 변경 사항이 있는 패키지를 지정합니다. **`[]`**로 감싸야 합니다. | `turbo run build --filter=[HEAD^1]` |

<Callout type="info">`-F`은 `--filter`의 별칭입니다.</Callout>

#### 필터링을 위한 마이크로 구문

- `!`: 선택 항목에서 대상을 무효화합니다.
- 패키지에 `...` 사용: 대상 기준으로 [패키지 그래프](/docs/core-concepts/package-and-task-graph#package-graph)의 모든 패키지를 선택합니다. 패키지 이름 **앞에** `...`을 쓰면 대상의 **dependents**를, 패키지 이름 **뒤에** `...`을 쓰면 대상의 **dependencies**를 선택합니다.
- Git 커밋을 사용하는 `...`: `[<from commit>]...[<to commit>]`을 사용하여 범위를 선택합니다.
- `^`: `...` 사용시 대상을 선택에서 생략합니다.

필터링에 대한 심층적인 토론과 실제 사용 사례를 보려면 [실행 중인 작업 페이지](/docs/crafting-your-repository/running-tasks)를 방문하세요.

#### 작업 식별자 사용

`package-name#task-name` 형식으로 특정 패키지에 대한 특정 작업을 실행할 수도 있습니다.

```bash title="Terminal"
turbo run web#lint
```

<Callout type="info">
  이 경우 작업의 종속성도 함께 실행됩니다. 종속성 없이 작업을 실행하려면
  [`--only` 플래그](#--only)를 사용하세요.
</Callout>

#### 고급 필터링 예

여러 필터를 결합하여 타겟을 더욱 구체화할 수 있습니다. 여러 필터는 통합으로 결합되며, 무효 필터는 통합 결과에서 패키지를 제거합니다.

```bash title="Terminal"
# 마지막 커밋 이후 변경된 `apps` 하위 디렉터리의 모든 패키지
turbo run build --filter={.apps/*}[HEAD^1]

# ./apps/admin을 제외한 `apps` 하위 디렉터리의 모든 패키지
turbo run build --filter=./apps/* --filter=!./apps/admin

# docs와 web 패키지에 대해 build 작업 실행
turbo run build --filter=docs --filter=web

# 'my-feature' 브랜치의 변경 사항에 의존하는 모든 것을 빌드
turbo run build --filter=...[origin/my-feature]

# 두 Git SHA 사이의 변경 사항에 의존하는 모든 것을 빌드
turbo run build --filter=[a1b2c3d...e4f5g6h]

# 다음 조건일 때 '@acme/ui'를 빌드:
# - 자신 또는 그 종속성이 이전 커밋 이후 변경되었을 때
turbo run build --filter=@acme/ui...[HEAD^1]

# 다음 조건에 해당하는 각 패키지를 테스트:
# - '@acme' 스코프에 있거나
# - 'packages' 디렉터리에 있거나
# - 이전 커밋 이후 변경되었을 때
turbo run test --filter=@acme/*{./packages/*}[HEAD^1]
```

### `--force`

기존 캐시된 아티팩트를 무시하고 모든 작업을 다시 실행합니다.

<Callout type="info">`--force`은 기존 작업 캐시를 덮어씁니다.</Callout>

```bash title="Terminal"
turbo run build --force
```

[`TURBO_FORCE` 환경 변수](/docs/reference/system-environment-variables)를 통해 동일한 동작을 설정할 수도 있습니다.

### `--framework-inference`

기본값: `true`

작업에 대해 [프레임워크 추론](/docs/crafting-your-repository/using-environment-variables#framework-inference) 수행 여부를 지정합니다.

`false`인 경우 [자동 환경 변수 포함](/docs/crafting-your-repository/using-environment-variables#framework-inference)이 비활성화됩니다.

```bash title="Terminal"
turbo run build --framework-inference=false
```

### `--global-deps <file glob>`

해시할 전역 파일 시스템 종속성의 글로브를 지정합니다. 여러 패키지에 영향을 미치는 `.env`와 루트 디렉터리의 파일에 유용합니다.

```bash title="Terminal"
turbo run build --global-deps=".env"
turbo run build --global-deps=".env.*" --global-deps=".eslintrc" --global-deps="jest.config.ts"
```

<Callout type="info">
  항상 반영되도록 하려면, 해시에 포함할 파일 글로브를 `turbo.json`의
  [`globalDependencies` 키](/docs/reference/configuration#globaldeps)에 지정하는 것을 권장합니다.
</Callout>

### `--graph <file name>`

기본값: `dot`

이 명령은 `svg`, `png`, `jpg`, `pdf`, `json`, `html`, `mermaid` 또는 `dot` 그래프 파일을 출력할 수 있습니다.

[Graphviz](https://graphviz.org/)가 설치되지 않았거나 파일 이름이 제공되지 않은 경우 이 명령은 도트 그래프를 `stdout`으로 인쇄합니다.

```bash title="Terminal"
turbo run build --graph
turbo run build test lint --graph=my-graph.svg
```

<Callout type="info">
  **알려진 버그**: 현재는 해당 스크립트가 특정 패키지에 실제로 존재하지 않더라도,
  가능한 모든 작업 노드가 그래프에 추가됩니다. 실행에는 영향이 없지만, 그래프가
  관련 패키지와 작업 수를 과대하게 보여줄 수 있습니다.
</Callout>

### `--log-order <option>`

기본값: `auto`

로그 출력 순서를 설정합니다.

기본적으로 `turbo`은 CI 환경에서 `grouped` 로그를 사용하고 다른 모든 곳에서는 `stream` 로그를 사용합니다. [터미널 UI](https://turborepo.dev/docs/reference/configuration#ui)를 사용하는 경우에는 이 플래그가 적용되지 않습니다.

```bash title="Terminal"
turbo run build --log-order=stream
```

| 옵션 | 설명 |
| --------- | ------------------------------ |
| `stream` | 사용 가능한 즉시 출력 표시 |
| `grouped` | 작업별 출력 그룹화 |
| `auto` | `turbo`은 자체 경험적 방법을 기반으로 결정 |

### `--log-prefix <option>`

기본값: `auto`

작업을 실행할 때 생성되는 로그 줄의 `<package>:<task>:` 접두사를 제어합니다.

```bash title="Terminal"
turbo run dev --log-prefix=none
```

| 옵션 | 설명 |
| ------ | ------------------------------------------ |
| `task` | 로그에 `<package>:<task>:` 접두사를 강제로 추가 |
| `none` | 접두사 없음 |
| `auto` | `turbo`은 자체 경험적 방법을 기반으로 결정 |

### `--no-cache`

<Callout type="warn" title="더 이상 사용되지 않음">
  이 플래그는 더 이상 사용되지 않으며 향후 주요 릴리스에서 제거될 예정입니다.
  대신 [`--cache`](#--cache-options) 플래그를 사용하세요.
</Callout>

기본값 `false`

작업 결과를 캐시하지 않습니다.

```bash title="Terminal"
turbo run dev --no-cache
```

### `--daemon` 및 `--no-daemon`

**더 이상 사용되지 않음**: 데몬은 더 이상 `turbo run`에 사용되지 않습니다. 이러한 플래그는 무시되며 버전 3.0에서 제거됩니다.

데몬은 여전히 ​​`turbo watch` 및 Turborepo LSP에서 사용됩니다.

### `--output-logs <option>`

기본값: `full`

`turbo.json`에 정의된 경우 [`outputLogs`](/docs/reference/configuration#outputlogs)를 재정의하여 출력 로깅 유형을 설정합니다.

```bash title="Terminal"
turbo run build --output-logs=errors-only
```

| 옵션 | 설명 |
| ------------- | --------------------------------- |
| `full` | 모든 로그를 표시합니다 |
| `hash-only` | 작업의 해시만 표시 |
| `new-only` | 캐시 누락 로그만 표시 |
| `errors-only` | 작업 실패의 로그만 표시 |
| `none` | 모든 작업 로그를 숨깁니다 |

### `--only`

기본값: `false`

지정된 작업만 포함하도록 실행을 제한합니다.

#### 예

`turbo.json`을 고려하면:

```json title="./turbo.json"
{
  "$schema": "https://turborepo.dev/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"]
    },
    "test": {
      "dependsOn": ["^build"]
    }
  }
}
```

```bash title="Terminal"
turbo run test --only
```

이 명령은 각 패키지의 `test` 작업만 _만_ 실행합니다. `build`은 실행되지 않습니다.

또한 `--only`은 종속성을 제외하고 지정된 패키지의 작업만 실행합니다. 예를 들어 `turbo run build --filter=web --only`은 `web` 패키지의 `build` 스크립트를 **만** 실행합니다.

### `--parallel`

기본값: `false`

작업 종속성 그래프를 무시하고 패키지 전체에서 명령을 병렬로 실행합니다.

```bash title="Terminal"
turbo run lint --parallel
turbo run dev --parallel
```

<Callout type="info">
  `--parallel` 플래그는 보통 종료되지 않는 장기 실행 `dev` 또는 `watch`
  작업에 사용됩니다. `turbo@1.7`부터는 이런 작업을 대신
  [`persistent`](/docs/reference/configuration#persistent)로 구성하는 것을 권장합니다.
</Callout>

### `--preflight`

원격 캐싱이 구성된 경우에만 적용 가능합니다. 모든 캐시 아티팩트 및 분석 요청 전에 실행 전 요청을 보낼 수 있습니다. 후속 업로드 및 다운로드는 리디렉션을 따릅니다.

```bash title="Terminal"
turbo run build --preflight
```

`TURBO_PREFLIGHT=true` 시스템 변수를 통해 동일한 동작을 설정할 수도 있습니다.

### `--profile`

성능 분석을 위해 두 가지 실행 추적을 생성합니다.

- Chrome 추적 형식: [Perfetto](https://ui.perfetto.dev/)와 같은 도구에서 추적을 시각적으로 검사합니다.
- Markdown 형식: LLM 사용을 단순화하기 위해 Markdown 파일을 출력합니다.

```bash title="Terminal"
# 이름에 타임스탬프가 포함된 파일 생성
turbo run build --profile

# 지정한 이름의 파일 생성
turbo run build --profile=my-profile
```

### `---anon-profile`

이 플래그는 `--profile`과 동일하게 작동하지만 민감한 정보를 수정하려고 시도합니다. 이는 프로필을 공유하는 데 유용합니다.

권장 사항: `--anon-profile`이 파일 경로, 환경 변수 또는 식별 정보와 같이 비밀로 유지하려는 모든 정보를 수정했는지 확인하세요.

### `--remote-cache-timeout`

기본값: `30`

원격 캐시 작업에 대한 시간 제한을 초 단위로 설정합니다.

```bash title="Terminal"
turbo run build --remote-cache-timeout=60
```

### `--remote-only`

<Callout type="warn" title="더 이상 사용되지 않음">
  이 플래그는 더 이상 사용되지 않으며 향후 주요 릴리스에서 제거될 예정입니다.
  대신 [`--cache`](#--cache-options) 플래그를 사용하세요.
</Callout>

기본값: `false`

작업 출력을 읽고 캐싱하는 데 원격 캐시를 사용하여 모든 작업에 대해 로컬 파일 시스템 캐시를 무시합니다.

```bash title="Terminal"
turbo run build --remote-only
```

### `--summarize`

다음을 포함하여 실행에 대한 메타데이터가 포함된 `.turbo/runs`에 JSON 파일을 생성합니다.

- 영향을 받는 패키지
- 실행된 작업(타이밍 및 해시 포함)
- 캐시된 아티팩트에 포함된 모든 파일

```bash title="Terminal"
turbo run build --summarize
```

이 플래그는 다음과 같은 사항을 확인하기 위해 디버깅하는 데 도움이 될 수 있습니다.

- `turbo`이 `inputs` 및 `outputs`에 대한 glob 구문을 해석하는 방법
- 캐시 미스를 생성하기 위해 두 작업 실행 사이에 입력이 변경된 내용
- 시간이 지남에 따라 작업 타이밍이 어떻게 변했는지

<Callout type="info" title="요약 뷰어">
  Turborepo 기본 Run Summaries UI 뷰어는 없지만, 여러 커뮤니티 제작 도구를 사용할 수 있습니다:

- [https://turbo.nullvoxpopuli.com](https://turbo.nullvoxpopuli.com) - 실행 요약을 위한 웹 기반 UI 뷰어
- [`turborepo-summary`](https://github.com/charpeni/turborepo-summary) - Turborepo 실행 요약 JSON 출력에서 사람이 읽을 수 있는 보고서 생성
- [`turborepo-summary-action`](https://github.com/charpeni/turborepo-summary-action) - GitHub Action 작업 요약에 추가하기 위해 `turborepo-summary`을 래핑하는 GitHub Action

</Callout>

### `--token`

원격 캐싱을 위한 전달자 토큰입니다. `--team` 플래그와 함께 비대화형 쉘에서 실행하는 데 유용합니다.

```bash title="Terminal"
turbo run build --team=my-team --token=xxxxxxxxxxxxxxxxx
```

이 값은 [`TURBO_TOKEN` 시스템 변수](/docs/reference/system-environment-variables)를 사용하여 설정할 수도 있습니다. 둘 다 존재하는 경우 플래그 값이 시스템 변수보다 우선합니다.

<Callout type="info">
  [Vercel Remote Cache](https://vercel.com/docs/monorepos/remote-caching)를 사용하고
  Vercel에서 프로젝트를 빌드하는 경우에는 이 플래그를 사용할 필요가 없습니다.
  이 값은 자동으로 설정됩니다.
</Callout>

### `--team`

원격 캐시 팀의 슬러그입니다. `--token` 플래그와 함께 비대화형 쉘에서 실행하는 데 유용합니다.

```bash title="Terminal"
turbo run build --team=my-team
turbo run build --team=my-team --token=xxxxxxxxxxxxxxxxx
```

이 값은 [`TURBO_TEAM` 시스템 변수](/docs/reference/system-environment-variables)를 사용하여 설정할 수도 있습니다. 둘 다 존재하는 경우 플래그 값이 시스템 변수보다 우선합니다.

### `--ui`

출력에 사용할 UI를 지정합니다. `stream` 또는 `tui`을 허용합니다.

### `--verbosity`

로그 수준을 지정하려면 `--verbosity=<num>` 또는 `-v, -vv, -vvv`을 사용합니다.

| 레벨 | 플래그 값 | 속기 |
| ----- | --------------- | --------- |
| 정보 | `--verbosity=1` | `-v` |
| 디버그 | `--verbosity=2` | `-vv` |
| 추적 | `--verbosity=3` | `-vvv` |

```bash title="Terminal"
turbo run build --verbosity=2
turbo run build -vvv
```
